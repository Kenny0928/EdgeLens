# 手機 IP 相機與 RTSP 網路攝影機

## 需要準備的東西

- 已能開啟 EdgeLens 的電腦。
- 二選一：iPhone／Android 手機與提供 MJPEG 或 JPEG 快照的 IP 相機類 App；或提供 RTSP 的攝影機／開發板（例如 AMB82）。
- 電腦與相機都能連上、且允許彼此通訊的區域網路。
- App／設備提供的完整影像網址；有啟用驗證時，準備帳號與密碼。
- 手機支架與足夠電量。不同 App 是否能背景運作、鎖屏傳影像，請看該 App 說明。

Mac 的 iPhone 接續互通相機是另一種連線方式，請看 [電腦相機與 iPhone 指南](WEBCAM_IPHONE.md)。這篇的手機模式透過網路網址連線。

## 步驟

### A. iPhone／Android 的 IP 相機 App

1. 選擇能顯示 **MJPEG 串流網址**或**單張 JPEG 快照網址**的 App，依 App 指示允許相機與本機網路存取，啟動影像服務。
   **成功時：** 手機上有預覽，並顯示可供其他裝置連線的 IP、埠號及網址。
2. 電腦與手機連到同一個可互通的網路，抄下完整網址。
   **成功時：** 網址包含 `http://`（或 App 提供的 `https://`）、IP、必要的埠號與最後的路徑。不要只抄分享網頁或 QR Code 的介紹頁。
3. 分清楚兩種網址。以下只是格式範例，實際值以 App 為準：

   | 用途 | 網址範例 | 成功時在電腦瀏覽器看到什麼 |
   |---|---|---|
   | MJPEG 串流 | `http://192.168.1.20:8080/video` | 連續更新的影像。 |
   | 單張快照 | `http://192.168.1.20:8080/shot.jpg` | 一張照片；重新整理才更新。 |

4. 若 App 有帳密，記下其影像服務帳密，在瀏覽器先驗證，再關閉測試分頁。
   **成功時：** 電腦能看到影像。App 只提供雲端登入、HTML 播放頁或其他串流格式時，不能直接當作 MJPEG 網址使用。

### B. RTSP 攝影機與 AMB82 等開發板

1. 依設備官方說明啟用 RTSP 服務；開發板需先執行能提供 RTSP 的韌體／範例。
   **成功時：** 設備設定頁或序列埠輸出有 RTSP IP、埠號及路徑。USB 接線不等於已經有 RTSP 影像。
2. 抄下完整網址，格式通常是 `rtsp://IP:埠號/路徑`，例如 `rtsp://192.168.1.20:554/live`。
   **成功時：** 每個部分都來自你的設備。`/live` 不是通用路徑；有的設備不需要路徑，不能自行加上去。
3. 可先用 VLC 或 ffplay 開相同網址。
   **成功時：** 播放器有即時影像。測試完先停止播放，再回 EdgeLens。

AMB82 的連接埠、影像路徑、編碼格式都**依你的板子與範例而定**。例如官方 RTSP 範例會要求從序列埠取得 IP 與埠號，請依 [Ameba 官方 RTSP 範例說明](https://ameba-doc-arduino-sdk.readthedocs-hosted.com/en/latest/ameba_pro2/amb82-mini/Example_Guides/Multimedia/AutoDayAndNight.html) 核對；不要照抄別台裝置的網址。

## 在 EdgeLens 裡加入相機

### 手機／MJPEG

1. 按「新增相機」，選「網路相機（MJPEG／手機 IP 相機）」。
   **成功時：** 「手動輸入」顯示「網址」與「接收方式」。此來源要手動貼網址，不會自動找到手機。
2. 在「網址」貼上影像網址。MJPEG 選「連續串流」；單張 JPEG 選「定時抓一張」。
   **成功時：** 網址與接收方式配對正確。
3. 需要帳密時展開「進階」，填「帳號（選填）」及「密碼（選填）」。
   **成功時：** 帳號正確，密碼欄顯示遮蔽字元。不要把密碼放進網址。
4. 使用單張快照時，在「抓圖間隔」先保留 `500 ms`（約半秒一張）。按「加入」。
   **成功時：** 串流連續更新，或快照按照間隔更新。實際速度仍受相機及網路限制。

**密碼與重新開啟：** 透過「密碼（選填）」輸入的密碼不會存進 EdgeLens 設定檔。結束 EdgeLens 後再開啟，需要重新填密碼。請重新用「新增相機」手動輸入網址與帳密，避免直接開啟不含密碼的最近使用項目；若舊來源已開啟，先關閉它。

網址裡的密碼（例如 `rtsp://帳號:密碼@主機/…`）存檔時也會去掉，只留帳號，所以重新開啟後同樣要再輸入。**不要把密碼或權杖放在網址的 `?` 參數中**，那部分無法自動辨認。MJPEG 的帳密連線採 HTTP Basic 驗證，其他驗證方式需老師確認相容性。

### RTSP

1. 按「新增相機」，選「網路影像串流（RTSP）」，在「網址」貼上設備提供的網址。
   **成功時：** 位址、埠號與路徑都與設備資訊相同。
2. 展開「進階」，「傳輸方式」先選「TCP（穩定）」。
   **成功時：** 保留 TCP 選項。提示原文：
   > TCP 比較穩定；只有在 TCP 連不上時才試 UDP。
3. 按「加入」，等幾秒。
   **成功時：** 影像出現，物品移動時畫面跟著變化。
4. 設備確認有支援 UDP、但 TCP 連不上時，關閉這個來源，重新新增並改選「UDP（較快但容易破圖）」。
   **成功時：** 能正常播放；若頻繁破圖，請改回 TCP 並檢查網路。

RTSP 目前沒有獨立帳密欄位。有些設備使用 `rtsp://帳號:密碼@IP:埠號/路徑`，但這種完整網址目前可能存進設定檔；**不能套用上面 MJPEG 密碼欄位不保存的承諾**。需要驗證的設備請老師先確認連線與帳密管理方式。

## 常見問題

| 訊息原文 | 做什麼 | 看到什麼代表成功 |
|---|---|---|
| {target} 需要帳號和密碼，或是帳號密碼不對。請在「帳號」「密碼」欄位填入相機 App 上設定的帳密。 | 在「帳號（選填）」、「密碼（選填）」重新填 App 帳密；注意大小寫。錯誤文案簡稱帳號、密碼，實際欄名含「選填」。 | 重新加入後出現影像，不再顯示驗證錯誤。 |
| {target} 回應了錯誤代碼 {code}。請確認網址（包含最後面的路徑）有沒有打對。 | 核對最後的路徑與埠號；404 常表示路徑不對。 | 瀏覽器能開影像，EdgeLens 也能接收。 |
| 網址看起來不對：{target}。要以 http:// 開頭，例如 http://192.168.1.20:8080/video。 | 使用 App 提供的完整 HTTP 影像網址。 | 重新加入後不再顯示格式錯誤。 |
| 連不上 {target}，已經超過 {seconds} 秒沒有收到畫面。請檢查：IP 或網址有沒有打錯、電腦和相機是不是連到同一個 Wi-Fi、相機有沒有開機或沒電了。（詳細原因：{detail}） | 依序確認電源、App 是否仍在服務、IP、Wi-Fi；校園網路請老師確認裝置隔離。 | 電腦能連到影像來源。 |
| 網址看起來不對：{target}。要以 rtsp:// 開頭，例如 rtsp://192.168.1.20:554/live。 | 改用設備提供的 RTSP 網址；不要把網頁觀看網址當作 RTSP。 | 重新加入後不再顯示格式錯誤。 |
| 打不開影像串流 {target}。請檢查：網址有沒有打錯、電腦和相機是不是連到同一個 Wi-Fi、相機有沒有開機。 | 先用 VLC／ffplay 驗證；核對傳輸方式與設備影像格式。 | 播放器與 EdgeLens 都有影像。 |

程式的帳密提示原文：

> 確認帳號與密碼有沒有大小寫打錯。

MJPEG 的檢查提示原文：

> 先用電腦的瀏覽器開開看同一個網址，能看到畫面再回來試。

RTSP 的檢查提示原文：

> 可以先用 VLC 或 ffplay 開同一個網址，確認串流本身正常。

若同一個 Wi-Fi 還是連不到，請老師確認學校是否啟用裝置隔離；改用允許互通的教學網路。只看到手機自己的預覽，不代表電腦已經能連入。

## 進階（可略過）

### 延遲不是越高畫質越好

EdgeLens 的網路來源在背景持續讀資料，只保留最新一張，避免舊畫面越積越多。相機編碼、Wi-Fi 與播放器緩衝仍會造成延遲，不能保證零延遲。

1. 畫面太慢時，先在相機 App／設備降低解析度或串流負荷，再重新觀察。
   **成功時：** 在鏡頭前移動手掌，畫面跟上的時間縮短。
2. 使用「定時抓一張」時，可增大「抓圖間隔」減少請求量。
   **成功時：** 更新較慢但穩定。間隔不是保證的 FPS。

畫面顯示的「延遲」不是完整的鏡頭到螢幕延遲；網路來源的時間戳記在電腦解碼收到影像時才建立。請用實際動作比對，不要只看該數字。

### 斷線會怎麼處理？

- 已連線後短暫斷線，EdgeLens 會自動重連。等待間隔由約 `0.25 秒` 逐步加倍，最多等 `5 秒` 再試；一次連線本身也可能耗時。
- 連續失敗超過預設約 `10 秒`，可能顯示錯誤。第一次開啟失敗也可能更早出現錯誤，不保證一定等滿 10 秒。
- 出現錯誤畫面後，先修正網路與電源，再按「重試」，或選「相機 → 重試連線」。影像重新更新代表恢復。IP 或網址改變時，請重新新增來源。

### 沒有 RTSP 設備時

「網路影像串流（RTSP）」的「網址」也可填本機影片檔的完整路徑。按「加入」後，影片會循環播放。這只能練習操作，不能驗證 RTSP 網路、TCP／UDP 或 AMB82 硬體。
